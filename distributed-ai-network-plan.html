Core Insight The world's idle compute already exists. Every laptop, desktop, and smart device runs at 2–5% capacity most of the time. NEURON harvests that unused capacity — no new hardware, no new power draw, no new data centers.
🌍

Geographic Clustering

Nodes grouped by region. NL serves NL users. India serves India users. Sub-5ms latency within clusters.

🔁

BitTorrent Redundancy

Every model layer lives on 1,000+ nodes. If 900 go offline — inference continues. No single point of failure.

🪙

NEURON Coin

Nodes earn coins for serving requests. Users spend coins for inference. Coordinator takes a protocol fee.

🌱

Zero Carbon Footprint

No new manufacturing. Existing power draw. 1% extra CPU = ~0.1W per device. Greener than any data center.

How a Request Flows

# 1. User sends request to NEURON API POST api.neuron.network/v1/chat { "model": "neuron-7b", "messages": [...] } # 2. Coordinator identifies nearest cluster user_ip → geolocate → "Netherlands" → NL_CLUSTER # 3. Route to available nodes in that cluster NL_CLUSTER.get_available_nodes(layer_count=32) → [node_4, node_17, node_203 ...] # 4. Each node processes its layer slice node_4 → layers 1-8 → forward activations to node_17 node_17 → layers 9-16 → forward activations to node_203 node_203 → layers 17-24 → forward activations to node_91 node_91 → layers 25-32 → return token to coordinator # 5. Token returned, coin deducted from user user_wallet -= 0.001 NRN node_wallets += 0.0009 NRN # split between 4 nodes protocol_fee = 0.0001 NRN # 10% coordinator fee

The 1MB Agent — What It Does

neuron-agent/ ├── agent.py # main loop — phones home, accepts tasks ├── model_slice.py # holds + runs assigned model layer range ├── resource_guard.py # enforces 1-2% CPU cap, idles when user active ├── wallet.py # NEURON coin balance, auto-withdraw threshold ├── updater.py # silent auto-update from coordinator └── tray.py # system tray icon — status, earnings, pause # Agent behaviour rules: - Activates ONLY when machine is idle > 5 minutes - Hard cap: 2% CPU, 200MB RAM (for itself) - Model weights streamed in chunks — not all at once - Never touches user files, network traffic, or screen - All comms encrypted TLS 1.3 to coordinator - Open source — anyone can audit the code
03 — Build Plan

Phase by Phase — With Claude Code

PHASE 0
Week 1–2

Foundation — Proof of Concept on Your Own Machines

Use your Pavilion (192.168.1.x) and OptiPlex (192.168.1.10) as the first two nodes. No coin, no internet. Just prove the layer-split inference works locally.

  • Install llama.cpp on both machines
  • Download a 3B model, split layers manually between machines
  • Write basic Python socket communication between nodes
  • Run one inference request end-to-end across two machines
  • Measure latency: local LAN should be under 1ms per hop
Success Metric One sentence generated across two machines. Doesn't need to be fast — just needs to work.
PHASE 1
Week 3–6

Coordinator Server

Build the central brain. This is a FastAPI server on your OptiPlex that manages node registration, layer assignment, and request routing.

  • Node registration endpoint — nodes phone home on startup
  • Layer assignment algorithm — which node holds which layers
  • Health checking — detect dead nodes, reassign layers
  • Request queue — accept inference requests, route to nodes
  • Basic dashboard — see active nodes, requests, health
# Coordinator core endpoints POST /node/register # node announces itself GET /node/layers # what layers am I responsible for? POST /infer # user submits inference request GET /status # network health dashboard
PHASE 2
Week 7–10

The Agent — Installable Node Software

Package everything into a single installer. This is what volunteers install. Must be trustworthy, lightweight, and easy to remove.

  • Python packaged as standalone executable (PyInstaller)
  • Windows (.exe), Linux (.deb/.AppImage), Mac (.dmg)
  • Resource governor — hard 2% CPU ceiling
  • Idle detection — only runs when user is away
  • System tray UI — shows earnings, pause button, status
  • Auto-updater — pulls new versions from coordinator silently
  • Signed binaries — code signing certificate so OS trusts it
Critical The agent must be fully open source from day one. This is the only way to build trust with contributors. Anyone should be able to read every line of what runs on their machine.
PHASE 3
Week 11–16

NEURON Coin — Incentive Layer

Add the economic layer. Start simple: an ERC-20 token on Polygon (low gas fees). Upgrade to own chain later when volume justifies it.

  • Deploy ERC-20 token contract on Polygon testnet first
  • Integrate wallet into agent — auto-generate keypair on install
  • Coordinator mints rewards per verified inference contribution
  • User payment flow — buy NRN, spend on inference
  • Proof of Compute — challenge-response to verify honest work
  • Anti-cheat — detect nodes faking work without contributing
# Token economics (initial) Total supply: 1,000,000,000 NRN Node rewards: 60% # earned by contributors over time Foundation: 20% # you — for development + operations Ecosystem fund: 15% # grants, partnerships Liquidity: 5% # DEX liquidity pool at launch
PHASE 4
Month 5–8

Public Launch — First 1,000 Nodes

Open the network to the public. Target: developers and tech-savvy early adopters who like the green AI story and want to earn crypto passively.

  • Landing page with one-click installer download
  • Public dashboard — live node map, total compute, requests served
  • Developer API — OpenAI-compatible so existing apps can switch
  • Discord community for node operators
  • Referral system — earn bonus NRN for bringing new nodes
Success Metric 1,000 active nodes in 3 different countries. At least 100 real inference requests per day from external users.
PHASE 5
Month 9–18

Scale — 100K Nodes, Regional Clusters

Expand clusters geographically. India, EU, US, SEA. Begin running larger models as network density increases.

  • Geographic cluster management in coordinator
  • Automated cluster rebalancing as nodes join/leave
  • Support 7B, 13B models as cluster size allows
  • Mobile agent — Android/iOS background service (limited)
  • Enterprise API tier — SLA guarantees, dedicated node pools
  • NRN listed on a DEX (Uniswap / Raydium)
04 — Legal Structure

From Day One, Built Correctly

Do This Before Writing Any Public Code Legal structure must be established before public launch. Running a crypto token without proper legal entity exposes you personally to unlimited liability. This is not optional.
🏢

Entity Structure

Option A: BV in Netherlands (you're already there). ~€500 setup. Good for EU operations, clean tax structure.

Option B: Foundation (Stichting) for the protocol + BV for commercial operations. Common in crypto (Ethereum Foundation model).

🪙

Token Legal

NRN must be structured as a utility token, not a security. Key requirement: token gives access to compute, not profit-sharing.

Get a Dutch crypto lawyer to review tokenomics before launch. Budget: €2,000–5,000.

🔒

Privacy / GDPR

Agent runs in EU — GDPR applies. Agent must:
• Collect zero personal data
• Log only compute metrics
• Have clear privacy policy
• Easy uninstall = full removal

📄

Terms for Node Operators

Contributors must agree to:
• What the agent does/doesn't do
• Resource usage limits
• How earnings work
• Liability waiver
• Right to audit agent code

Legal Checklist — Phase 0 (Before Any Public Code)

  • Register BV or Stichting in Netherlands
  • Open business bank account
  • Consult Dutch crypto lawyer on token classification (utility vs security)
  • Draft contributor Terms of Service and Privacy Policy
  • Register NEURON trademark in EU
  • Open source license decision — Apache 2.0 recommended for agent code
  • Get code signing certificate for agent binaries (DigiCert, ~€300/year)

05 — Risks & Mitigations

What Can Go Wrong

Risk Severity Mitigation
Malicious nodes return false outputs HIGH Redundant computation — send same layer to 3 nodes, use majority vote. Slash coin stake of cheaters.
Antivirus flags agent as malware HIGH Code signing certificate + open source + submit to major AV vendors for whitelisting before launch.
Latency too high for useful inference HIGH Geographic clustering keeps hops local. Start with small models (1B-3B) that need fewer layer hops.
Token classified as security by regulators HIGH Legal opinion letter before launch. Design tokenomics as pure utility. No profit-sharing, no dividends.
Users don't trust agent on their machine MEDIUM Full open source. Independent security audit. No data collection by design. Easy one-click uninstall.
Coordinator is single point of failure MEDIUM Run 3 coordinator instances in different regions. Move to fully decentralized coordinator in Phase 5.
Competing project launches first MEDIUM Your differentiation is green AI + consumer devices (not GPU miners). Different market from Render/Akash.
Node operator loses money (electricity > earnings) LOW 1% CPU = ~0.1W extra. Negligible cost. Earnings dashboard must show real-time ROI clearly.

08 — Strategic Options

Three Paths — Pick One

New Intelligence — Updated After Competitor Research Bittensor ($3.5B), Gensyn ($80M, just launched April 2026), and io.net (80,000 CPUs already) all exist. This changes the strategic picture. You must pick one of three paths before writing a single line of code.
PATH A

Launch as a Bittensor Subnet

FASTEST

Build NEURON as a subnet inside Bittensor's existing network. Their blockchain, their validators, their liquidity — you build the consumer-agent layer on top as a specialized subnet focused on CPU-based inference from normal devices.

ADVANTAGES
  • No blockchain to build — already exists
  • No token launch — use TAO subnet emissions
  • Existing community of 10,000+ miners
  • Regulatory clarity — TAO is established
  • Can launch subnet in weeks not years
  • Bitstarter crowdfunding available for subnets
DISADVANTAGES
  • Dependent on Bittensor's success
  • Subnet registration costs TAO upfront
  • Limited control over protocol rules
  • Revenue split with Bittensor network
  • Competitive — 128 subnets already exist
Best If You want to ship something real in 3–6 months, validate the consumer-device idea, and build a user base before committing to a standalone network.
PATH B

Build Standalone — Own Chain, Own Coin

HARDEST

The original plan. NEURON as a fully independent network with its own blockchain, own token (NRN), own coordinator, own agent. Maximum control, maximum upside, maximum risk.

ADVANTAGES
  • Full control of protocol and economics
  • 100% of token value stays in ecosystem
  • Can design specifically for consumer CPUs
  • No dependency on other networks
  • Highest potential upside if it works
DISADVANTAGES
  • 2+ years to build properly
  • Competing with Gensyn ($80M) and io.net directly
  • Token launch in 2026 is a crowded, skeptical market
  • Needs funding — can't be built alone for free
  • Regulatory exposure as token issuer
Best If You secure €500K+ in funding, have a technical co-founder, and are willing to commit 3+ years full time.
PATH C

Partner with io.net as Consumer CPU Layer

MOST REALISTIC

io.net has 80,000 CPUs but their onboarding requires staking, 12-hour verification, and technical setup. You build the missing piece — the frictionless consumer agent — and pitch it to io.net as a partnership or acquisition target. You solve their supply problem. They give you distribution.

ADVANTAGES
  • Existing network to plug into immediately
  • No blockchain, no token needed initially
  • Acquisition potential — valuable exit
  • Proof of concept is enough to start conversations
  • Fastest path to 1M nodes
DISADVANTAGES
  • You build the tech, they own the upside
  • Dependent on io.net's direction
  • Less founder control
  • Partnership talks take time
Best If You want to validate the agent first, show it works at 100 nodes, then open conversations with io.net, Gensyn, or Bittensor from a position of demonstrated value — not just an idea.

Recommended Sequence

# The pragmatic path for one person with no funding Step 1 (Now → Month 3): Build the agent. Prove it works on 10 machines. Language: Python. Zero blockchain. Zero coin. Just: installs silently, caps at 2% CPU, runs inference. Step 2 (Month 3 → Month 6): Launch as Bittensor subnet (Path A). Get first 500 real nodes. Prove the consumer UX works. This is your proof of concept AND your case study. Step 3 (Month 6 → Month 12): Decision point based on traction: - Subnet doing well → keep building on Bittensor - io.net notices you → explore partnership (Path C) - Raising money → go standalone (Path B) # Never build a blockchain before you have 1,000 users. # Never launch a coin before you have a working product.
